# PCON.IDL fast-forward

2026-08-25. The 8051 half of the sleep-not-spin wave, after the pico (110x,
deployed) and AVR (`bw-board b1cc57e`) halves.

## What was wrong

`core.c` always implemented idle correctly: with PCON.IDL set it stops
executing opcodes, parks the PC, keeps the timers counting, and clears IDL when
an enabled interrupt vectors. It just never got any FASTER, because
`stc12_advance_to` ground one oscillator clock at a time either way. Measured
on an 11.0592 MHz STC12 before the change:

| firmware | wall per 1 s of sim | sim/wall |
|---|---|---|
| busy-spin (`SJMP $`) | 0.643 s | 1.55 |
| PCON.IDL set | 0.732 s | 1.37 |

Idling was **slower than not idling**. Splitting the idle cost: the CPU `tick()`
is 65 % of it and the peripheral `stc12_tick()` the other 35 %, so skipping only
the CPU caps the win near 1.5x. A real jump has to skip both.

## Why the guard is narrow rather than complete

Enumerating the next event across T0, T1, the baud-rate timer, the PCA, the ADC
and the watchdog is the kind of enumeration that breaks firmware silently.
bw-board's avr8js fast-forward shipped a first cut that fell through a sleep,
and real third-party firmware — not its unit tests — caught it.

So `stc12_idle_skip_clocks` does not enumerate. It asks one question: **is
Timer 0 the only thing that can happen next?** If anything else is armed, or
anything is uncertain, it returns 0 and the emulator behaves exactly as before.
The optimisation is inert unless it is provably safe.

Refused when: not STC12/STC15 · `skip_timers` false · PCON.IDL clear or PD set ·
EA or ET0 clear · any interrupt already pending · T0 stopped, gated, or in
counter mode · T0 in mode 0 or 3 · T1, the BRT, the PCA, the ADC or the
watchdog running · an STC15 clock-out enabled.

It also **never skips the overflow**: the jump stops at least one counter tick
short and moves only whole ticks, so the 12T prescaler stays put and TF0, the
PCA's T0 drive, the clock-out toggle and the interrupt vectoring all still
happen on the normal per-clock path.

## What it is worth, end to end

Real examples, generated by sb3-creator, compiled by SDCC, run in this
emulator. 200 ms of simulated time:

| example | code | fast-forward off | on | clocks slept | state identical |
|---|---|---|---|---|---|
| 76-multimeter | 3924 B | 563 ms | 14 ms | 96.16 % | yes |
| 61-console-pong | 6581 B | 259 ms | 19 ms | 96.23 % | yes |

"State identical" means the PC, elapsed simulated time, all 128 SFRs and all
128 bytes of IRAM agree between the two runs.

## The gates

- `test_idle_fastforward.c` — native differential, plus each guard exercised on
  its own, plus the tick count checked against arithmetic.
- `test_wasm_idle.mjs` — the same through the WASM boundary, which the native
  oracle structurally cannot cover.
- `test_corpus_canary.mjs` — the `stc` sibling's twelve real firmware images,
  each run both ways. None of them idles, so the expected and observed result
  is that the optimisation is completely inert over all of it.

No wall-clock budget appears in any of them. Three machines have shown timing
budgets fire falsely under load, and a gate that goes red for the wrong reason
gets ignored for the right ones.
